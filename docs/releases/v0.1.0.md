# Helium-III v0.1.0 Release Notes

**Release Date:** not released yet (draft, 2026-11-12)  
**Baseline:** TriliumNext/Trilium v0.107.0 (upstream commit `55c8d2f`)  
**Target Host:** Sol (`https://notes.empyrean.cc`)  
**Repository:** `Vandaemonium/Helium-III`

---

## Overview

Helium-III v0.1.0 is the first tagged release of Helium-III, a personal fork of TriliumNext/Trilium maintained for `notes.empyrean.cc`. It establishes the fork baseline with an isolated deployment and builds two features into the app: **Home** on the root note and **Quick Notes** in the right sidebar.

> **Packaging change.** Earlier drafts shipped Home and Quick Notes as installable note-subtree modules (`empyrean.home-panel`, `empyrean.quick-notes`). VC decided on 2026-11-12 that both are built into the UI instead, even though that breaks the modular design. The module packages, their ZIP builders and their ETAPI install/activate/uninstall scripts are removed. There is no migration from installed modules (Sol only held test data); leftover module notes are ignored, never touched, and can be deleted by hand.

## Included Components

### 1. Fork Baseline (`v0.107.0` / `55c8d2f`)
- Forked directly from upstream TriliumNext/Trilium v0.107.0 (`55c8d2f`).
- Core codebase, schema (DB 242, sync protocol 41), and APIs remain aligned with upstream v0.107.0.
- Repository-level OpenSpec tracking under `openspec/changes/`.
- Deployment isolation contract:
  - Dedicated container (`trilium-notes`) on Sol with freshly initialized data directory (`~/docker/config/trilium-notes`).
  - Served behind Caddy at `https://notes.empyrean.cc`.
  - Complete process and data isolation from stock Trilium (`https://trilium.empyrean.cc`).

### 2. Home (built in)
- Opening the root note in its normal view shows Home instead of root's own content: **Recent**, **Pinned** (`#pinned`) and **Inbox** (`#inbox` notes and the children of `#inbox` folders).
- Root's type, content, attributes and children are never changed; its source and attachments views still work.
- Leaves out protected notes (even while unlocked), hidden notes, archived notes by default, and notes of the retired modules. Filtering happens before the section limits.
- Configuration (limits, labels) is JSON in the hidden note `_heliumHomeConfig`, seeded once with Recent 8, Pinned 12, Inbox 10; edits survive restarts.
- User Guide: *UI Elements → Home*.

### 3. Quick Notes (built in)
- A **Quick Notes** tab in the right sidebar, for every note type and independent of the AI option; on phones it is a tab of the note panel.
- Explicit Save; the first nonblank line is the title; text is escaped into one native text note in the **Quick Notes** folder.
- Draft, save state, search and view are kept in memory for the window, so closing the sidebar or the phone panel loses nothing; an unload warning covers an unsaved draft.
- A refused save keeps the draft; a save with no answer is marked uncertain and blocks a retry until the user confirms checking.
- Cards for the folder's direct text children; pin/archive/restore with the note's own `heliumQuickPinned`/`heliumQuickArchived` labels; title and body search within Active or Archived.
- Protected notes are never listed or changed, even while unlocked; a protected, deleted or hidden folder blocks saving instead of creating the note elsewhere. The server enforces the same checks.
- Setup creates one visible folder `Quick Notes` under root with the deterministic ID `heliumQuickNotes` (branch `root_heliumQuickNotes`), recorded in the hidden note `_heliumQuickConfig`. An unrelated top-level note already named `Quick Notes` is never claimed: the panel reports the conflict.
- User Guide: *UI Elements → Right Sidebar → Quick Notes tab*.

### Storage, options and API
- Hidden notes `_helium` → `_heliumHomeConfig`, `_heliumQuickConfig` (JSON). Hidden is not encrypted.
- Options *Other → Home and Quick Notes*: `heliumHomeEnabled`, `heliumQuickNotesEnabled` (synced, default on). They switch the presentation only.
- Internal routes shared by server, desktop and standalone: `GET /api/helium/home`, `GET|POST /api/helium/quick-notes`, `POST /api/helium/quick-notes/setup`, `PUT /api/helium/quick-notes/:noteId/state`. No ETAPI token, no backend scripting.

## Upgrading from the module drafts

Nothing to run. The built-in features do not read the old `Home Panel Config` or Quick Notes config, and do not adopt the old `Quick Notes — Notes` folder. Old module notes (code, config, host Render Notes) stay in the tree until removed by hand; Home does not list them.

## Known Limits

1. **Runtime verification target:** verified on a build of this fork (app 0.107.0, DB 242, sync 41) on an isolated loopback instance with a fresh database, not on the production Sol container.
2. **Device verification:** the phone layout was checked with Chromium mobile emulation at 375 CSS pixels. Physical phone testing (iOS Safari, Android Chrome) remains open.
3. **Drafts are per window and in memory:** a reload or a crash loses an unsaved draft (the unload warning covers deliberate closes). No offline queue.
4. **Recent scans all notes:** Home's Recent section sorts every eligible note in memory on each refresh; fine for a personal database, not tuned for very large ones.
5. **Feature boundaries:** no rich-text composer (cards open the native editor), no checklists, colors, reminders or Markdown mirroring.
