# Helium-III v0.1.0 Release Notes

**Release Date:** 2026-11-12  
**Baseline:** TriliumNext/Trilium v0.107.0 (upstream commit `55c8d2f`)  
**Target Host:** Sol (`https://notes.empyrean.cc`)  
**Repository:** `Vandaemonium/Helium-III`

---

## Overview

Helium-III v0.1.0 is the initial tagged release of Helium-III, a personal fork of TriliumNext/Trilium maintained for `notes.empyrean.cc`. This release establishes the fork baseline with an isolated deployment architecture and introduces two independently installable note-subtree feature modules: Home Panel and Quick Notes.

---

## Included Components

### 1. Fork Baseline (`v0.107.0` / `55c8d2f`)
- Forked directly from upstream TriliumNext/Trilium v0.107.0 (`55c8d2f`).
- Core codebase, schema (DB 242, sync protocol 41), and APIs remain aligned with upstream v0.107.0.
- Repository-level OpenSpec tracking introduced under `openspec/changes/`.
- Deployment isolation contract:
  - Dedicated container (`trilium-notes`) on Sol with freshly initialized data directory (`~/docker/config/trilium-notes`).
  - Served behind Caddy at `https://notes.empyrean.cc`.
  - Complete process and data isolation from stock Trilium (`https://trilium.empyrean.cc`).

### 2. Home Panel Module v0.1.0 (`empyrean.home-panel`)
- **Package:** `empyrean.home-panel` v0.1.0 (`modules/home-panel/`, PR #2, commit `c7e579e`).
- **Description:** Independently installable personal Home dashboard module providing high-level workspace overview.
- **Features:**
  - Preact/JSX Render Note (`HomePanelRoot.jsx`) with `@scope`-scoped styling.
  - Child frontend JavaScript submodule (`HomePanelQueries.js`) for config normalization and note lookups.
  - Three distinct overview sections:
    - **Recent Notes:** Configurable list of recently updated notes.
    - **Pinned Notes:** Quick access to notes tagged `#pinned` (or custom pin label).
    - **Inbox Preview:** Direct links to notes filed under the designated Inbox root.
  - Supports dual display modes: standalone Render Note (`Home`) or embedded child widget within a native Trilium Dashboard collection.
  - Strict separation of executable code notes from user configuration and user notes.

### 3. Quick Notes Module v0.1.0 (`empyrean.quick-notes`)
- **Package:** `empyrean.quick-notes` v0.1.0 (`modules/quick-notes/`, draft PR #4, commit `0da8091`).
- **Description:** Lightweight text capture and card board designed for rapid input on desktop and mobile viewports.
- **Features:**
  - Dedicated text composer with explicit Save button; draft preserved in memory during failures or navigation.
  - First nonblank line automatically supplies the note title; body safely converted with HTML escaping.
  - Empty or whitespace-only drafts rejected.
  - Responsive card grid adapted for desktop displays and 375 CSS-pixel mobile viewports.
  - Scoped title and body search restricted to the active view.
  - Reversible pin and archive functionality using module-scoped metadata (`heliumQuickPinned`, `heliumQuickArchived`) without affecting global tags (`#pinned`, `#archived`, `#inbox`).
  - Native note editor navigation (`api.activateNote`) directly from cards; rich text is previewed safely as text without modifying native note bodies.
  - Security boundaries: excludes all protected notes (even when unlocked), refuses protected destination folders, requires zero backend scripting, contains no embedded credentials, and executes no external network requests.
  - Dedicated retained storage folder keeping user captures separate from the global Inbox.

## Install Notes for Modules

Modules in Helium-III follow the versioned note-subtree contract. They are distributed as inert ZIP packages and managed via ETAPI using operator lifecycle scripts:

### Prerequisites
- Operator access to `HELIUM_URL` and `HELIUM_ETAPI_TOKEN` set in the environment.
- HTTPS or loopback HTTP connection (plain HTTP redirects are refused).

### Packaging
Build the importable ZIP archives from source:
```bash
# Home Panel
node modules/home-panel/scripts/build-package.mjs

# Quick Notes
node modules/quick-notes/scripts/build-package.mjs
```
Artifacts are generated deterministically under `modules/<module>/dist/`.

### Lifecycle Commands
Each module provides an operator lifecycle controller (`scripts/lifecycle.mjs`):

1. **Inert Install:**
   Imports the module code tree under native `root` (virtual `_hidden` rejects new children) and creates retained data/config/host notes. Entry points remain inert under `disabled:renderNote`:
   ```bash
   node modules/<module>/scripts/lifecycle.mjs install
   ```

2. **Activation:**
   Promotes `disabled:renderNote` to active `renderNote`. Clients must be reloaded to display the interface:
   ```bash
   node modules/<module>/scripts/lifecycle.mjs activate
   ```

3. **Disable:**
   Reverts relation to `disabled:renderNote`. Immediately halts module rendering across reloaded clients while retaining all code, configuration, and user notes:
   ```bash
   node modules/<module>/scripts/lifecycle.mjs disable
   ```

4. **Guarded Code-Only Uninstall:**
   Removes only owned code notes while preserving user data folders, notes, scoped attributes, and configuration notes. Requires an exclusive maintenance window, an application-consistent backup, and approval of the generated plan hash:
   ```bash
   # Preview the exact deletion inventory
   node modules/<module>/scripts/lifecycle.mjs preview-uninstall

   # Execute removal with confirmed plan hash
   node modules/<module>/scripts/lifecycle.mjs uninstall <plan-sha256> --maintenance-confirmed
   ```

5. **Reinstall / Upgrade:**
   Reinstalls code notes while reconnecting to existing retained configuration and data notes without duplicate entries.

## Known Limits

1. **Runtime Verification Target:**
   - Testing was conducted against the official upstream Trilium v0.107.0 Linux-x64 binary (`d83d7151f1c6d4292be88d8d34008f409b252f7f`), not against the exact Helium-III fork container build or production Sol runtime.
2. **Device Verification:**
   - Mobile UI verification was performed using Chromium desktop and mobile-UA emulation at 375 CSS pixels. Physical phone testing (iOS Safari, Android Chrome) remains open.
3. **Draft Implementation Status:**
   - Quick Notes v0.1.0 is currently on draft PR #4 (`0da8091`) and has not been approved for production deployment.
4. **ETAPI Deletion Concurrency:**
   - ETAPI note deletion does not provide an atomic server-side graph lock. While leaf rechecks, plan hashing, and maintenance confirmation minimize risk, a concurrent edit race exists if operations occur outside an exclusive maintenance window.
5. **Review Gate Status:**
   - Jev frontend review returned `jev_unsure`; lifecycle review recommended a draft PR with maintenance-only removal. Independent security and data review have not yet been completed.
6. **Feature Boundaries (v1 Non-Goals):**
   - No offline queue or background autosave (captures require an online connection).
   - No custom rich-text/formatting editor within cards (native editor handles rich text).
   - No checklists, card color tagging, reminders, or filesystem Markdown mirroring in v1.
7. **Protected Sessions:**
   - Adapter tests verify exclusion of locked/unlocked protected notes and rejection of protected folders, but end-to-end protected-session timeout transitions require verification on the target build.
